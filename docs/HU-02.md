# HU-02 — Real Persistence and Lifecycle Management

## Context

For Eventify to behave like a real platform, in-memory storage is not enough. This HU moves the system to **real database persistence**, completes the **CRUD lifecycle**, and adds **pagination** on listing endpoints so the API scales without overwhelming the client or the server.

## User story

> **As** a Catalog Administrator
> **I want** to manage the full lifecycle of records in a real database
> **So that** information is persistent, editable, and easy to query at scale.

## Stack introduced in this HU

| Category | Technology |
|---|---|
| Persistence | Spring Data JPA + Hibernate 7 |
| Database | H2 in file mode (`./data/eventifydb.mv.db`) |
| Repository testing | `spring-boot-starter-data-jpa-test` with `@DataJpaTest` |
| Web DB console | `JakartaWebServlet` manually registered at `/h2-console/*` |

## Architecture

The persistence layer is inserted between the services and the database:

```
Controller → Service → Repository (JpaRepository) → Hibernate → H2 (file)
```

### Changes per package

- `com.eventify.model` — POJOs converted into `@Entity` classes with `@Id`, `@GeneratedValue(IDENTITY)` and `@Column(nullable = false, length = ...)`.
- `com.eventify.repository` — interfaces extending `JpaRepository<T, Long>` with derived queries: `findByNameContainingIgnoreCase`, `findByDateAfter`, `findByDateBetween`, `findByCapacityGreaterThanEqual`.
- `com.eventify.service` — services delegate to repositories. Every `create()` defensively calls `setId(null)` so the ID is always assigned by the database.
- `com.eventify.exception` — new package: `ResourceNotFoundException`, `ErrorResponse` (record), and `GlobalExceptionHandler` annotated with `@RestControllerAdvice`.
- `com.eventify.controller` — full CRUD endpoints plus paginated listing using `Pageable`.
- `com.eventify.config` — `H2ConsoleConfig` (Spring Boot 4 workaround) and an idempotent `DataSeeder`.

## Endpoints

Same contract for both resources (`/api/events` and `/api/venues`):

| Method | Path | Possible status codes |
|---|---|---|
| `POST` | `/api/{resource}` | `201`, `400` |
| `GET` | `/api/{resource}` | `200`, `204` |
| `GET` | `/api/{resource}/{id}` | `200`, `404` |
| `PUT` | `/api/{resource}/{id}` | `200`, `400`, `404` |
| `DELETE` | `/api/{resource}/{id}` | `204`, `404` |

### Pagination

The listing endpoints accept the standard Spring Data query params:

```
GET /api/events?page=0&size=10&sort=name,asc
GET /api/events?page=0&size=5&sort=date,desc
GET /api/venues?page=0&size=10&sort=capacity,desc
```

Defaults: `page=0`, `size=20`, no sort.
- `200 OK` with `content`, `totalElements`, `totalPages`, `number`, `size`, etc.
- `204 No Content` when the requested page is empty.

### Error handling

Every error response shares the same shape (`ErrorResponse`):

```json
{
  "timestamp": "2026-05-17T19:52:05",
  "status": 404,
  "error": "Not Found",
  "message": "Event with id 9999 was not found",
  "path": "/api/events/9999"
}
```

| Exception | HTTP status |
|---|---|
| `ResourceNotFoundException` | `404 Not Found` |
| `IllegalArgumentException` | `400 Bad Request` |

## Persistence

Relevant configuration in `application.properties`:

```properties
spring.datasource.url=jdbc:h2:file:./data/eventifydb;DB_CLOSE_DELAY=-1;MODE=PostgreSQL;AUTO_SERVER=TRUE
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
```

- **File mode:** data survives application restarts.
- **`AUTO_SERVER=TRUE`:** allows the web console and the app to open the DB simultaneously.
- **`ddl-auto=update`:** Hibernate applies schema diffs without dropping existing data.

The `./data/` directory is git-ignored.

### Idempotent DataSeeder

The seeder runs on every startup but **only inserts when the corresponding table is empty** (`repository.count() == 0`). This prevents duplicate inserts on restart and preserves user-created data.

## Spring Boot 4 notes

Three quirks worth keeping in mind:

1. **H2 console is not auto-configured:** must be registered manually with a `ServletRegistrationBean<JakartaWebServlet>` (`H2ConsoleConfig.java`).
2. **`@DataJpaTest` moved:** now lives in `org.springframework.boot.data.jpa.test.autoconfigure` and requires the dedicated starter `spring-boot-starter-data-jpa-test`.
3. **Trailing slash matching disabled:** hitting `/h2-console` (no trailing `/`) returns 404 because Spring 6+ removed automatic trailing slash matching. Use `/h2-console/`.
